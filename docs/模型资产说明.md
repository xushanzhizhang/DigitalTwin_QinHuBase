# 模型资产说明

> 说明《场景图及建模要求/建模/qinhu_base_digital_twin.glb》是怎么被工程化接入的、
> 优化了什么、对模型本身有什么约定。
> 面向：后续要继续改模型或改前端的人。

## 1. 资产清单

| 文件 | 用途 | 是否运行时必需 |
|---|---|---|
| `qinhu_base_digital_twin.glb` | 完整基地模型（15.4 MB） | **是** |
| `scene_manifest.json` | 区域、设施、构件的 ID 与坐标、数据键 | **是** |
| `qinhu_lake.glb` / `qinhu_hort.glb` / `qinhu_peony.glb` / `qinhu_smart.glb` | 分区单独导出，供单区预览用 | 否 |
| `设施设备ID清单.csv` | 设备坐标与接口清单（给现场核对用） | 否 |
| `index.html` | 建模阶段的三维预览页 | 否 |

运行时只加载主 GLB 与 manifest。文件不进 `frontend/`，由后端单独挂了一个静态路由：

```
GET /assets/model/qinhu_base_digital_twin.glb
GET /assets/model/scene_manifest.json
```

对应 `backend/app.py` 里的 `MODEL_DIR` 挂载。**重新导出模型后直接覆盖原文件即可**，
前端刷新就能看到，不需要拷贝、不需要重新打包。

## 2. 模型结构（读代码前先看这段）

场景层级：

```
world
├── 00_基地环境          地面、围栏、道路、庭院灯、树、标识
├── 01_入口湖景与桥梁    东侧入口、琴湖、湖心岛、木栈桥、驳岸石
├── 02_园艺植物生产实训中心
├── 03_芍药种植资源创新基地
└── 04_数智农业实践研学中心
```

规模：**945 个网格 / 858,375 三角面 / 43 种材质 / 40 张内嵌贴图**。

其中约 **63 万面是温室内部的"作物行"**（`*_内部作物行`），单个温室 3~5 万面，
芍药基地三栋合计 48 万面 —— 这是模型面数的主要来源，也是优化时要盯住的对象。

## 3. 加载流水线（`frontend/js/scene/site.js`）

```
GLTFLoader 载入
   ↓
1. 区域识别      按 5 个区域组名建立"对象 → 区域"索引
   ↓
2. 材质工程化    薄膜/透光板/钢/石材/草地的 PBR 参数修正
   ↓
3. 阴影策略      只给承重构件投影，作物行/膜/防护网不投影
   ↓
4. 构件索引      风机叶片、传感器状态灯、作物行、棚膜各自成表
   ↓
5. 静态合并      按（区域 × 材质）合并，945 → 约 380 个网格
   ↓
6. 水面替换      "Pond water" → 自定义水面着色器 + 平面反射
   ↓
7. 周边地面      补一块大地面，消除"模型底座漂浮"感
   ↓
8. 暴露孪生 API  setRegion / applyState / update
```

### 3.1 材质工程化做了什么

| 材质 | 处理 |
|---|---|
| `Translucent greenhouse film` | 半透（opacity 0.55）、双面、不写深度、环境反射 0.9 |
| `Greenhouse polycarbonate wall` / `*透光板` | opacity 0.42、粗糙度 0.16 |
| `Pond water` | 整体替换为自定义着色器（波纹 + 菲涅尔 + 平面反射） |
| `Galvanized steel` / `*steel` | 粗糙度压到 ≤0.45、金属度抬到 ≥0.65 |
| `Turf • natural grass` | 粗糙度 0.96，去掉不自然的高光 |
| `Foliage*` / `Peony petals` | 双面、粗糙度 0.82 |
| 其他 | 统一补 `envMapIntensity`，避免金属件发死灰 |

### 3.2 阴影策略

- **投影**：钢结构拱架、檩条、排风机、门柱门头、墙体、屋面、桥、栈道、栏杆、灯杆、树木。
- **不投影**：室内作物行（63 万面，投影代价过大）、棚膜、透光板、防护网、驳岸块、地面、水面。
- 结果：投影对象从"全部"降到约 100 个，阴影贴图 2048²，能覆盖整场。

### 3.3 静态合并

`mergeStatic()` 按 `区域 + 材质` 分组，把静态几何 applyMatrix4 到世界坐标后合并。
**保留独立对象**的白名单（正则 `KEEP_SEPARATE`）：

```
叶片 | 电机轴 | 状态灯 | 内部作物行 | 拱形棚膜 | 透光板 | 传感器 | 控制柜 | 水肥 | 储罐 | 标牌 | 门柱 | 门头
```

合并效果：**945 → 约 380 个网格**，draw call 从 945 降到约 390（剩余大头是 168 个风机叶片，
它们要各自转，无法合并）。

### 3.4 水面

`Pond water` 材质被换成 `water.js` 里的着色器：

- 两层法线波动（米级波长）+ 菲涅尔 + 太阳镜面高光；
- 每帧用镜像相机渲一张 512² 的图做**平面反射**（岸石、栈桥、温室都会映进水里）；
- 水色取浑绿，不用饱和青蓝 —— 实景里的水就是这个颜色。

#### 抗闪烁（重要，改这个着色器前必读）

水面一开始会出现"白点一闪一闪"，尤其沿湖岸一带。这是典型的**镜面走样**：
扰动后的法线在远处只占亚像素，高光每帧跳到相邻像素上，就成了一点一点的白。

处理办法（都在 `water.js` 里，注释有说明）：

| 手段 | 参数变化 |
|---|---|
| 高光更宽更弱并封顶 | 指数 900 → 90，强度 2.2 → 0.7×near^1.5，`min(spec, 0.30)` |
| 法线强度按距离衰减 | `near = clamp(1 - dist/190, 0.10, 1)`，乘到法线上 |
| 波纹推进速度减半 | 相位系数 0.008/0.006 → 0.0040/0.0025 |
| 反射采样 4 抽头均值 | 采样半径 0.004~0.0085（按距离） |
| 倒影扰动按距离收敛 | 0.012 → 0.008×near |

**实测**（1000×640，冻结动画后按 40 ms 步长取样，逐像素取最大帧间差）：

| 阶段 | 最大差值 | 差值 >60 的像素 |
|---|---|---|
| 修复前 | 392 | 1050 |
| 修复后 | 53 | 0 |
| 隐藏水面的基线 | 3 | 0 |

> 基线 3 说明闪烁全部来自水面着色器，场景其余部分（风机、状态灯、阴影）是稳定的。
> 调试钩子：模型页可在控制台执行 `__freezeWater = true; __waterT = 0.4` 冻结水面相位，便于逐帧比对。

## 4. 命名契约（改模型时务必保留）

绑定逻辑靠**模型自身的节点命名**识别构件，不靠硬编码坐标。
下面这些后缀（`节点名最后一个下划线之后的部分`）是接口：

| 命名后缀 | 含义 | 运行时用途 |
|---|---|---|
| `排风机叶片` / `循环风扇叶片` | 风机叶片 | 通风开度 → 转速 |
| `传感器状态灯` | 传感器指示灯 | 分区健康度 → 灯色 + 呼吸 |
| `内部作物行` | 温室作物 | 墒情 → 作物色相 |
| `拱形棚膜` | 棚膜 | 外遮阳开度 → 膜变暗、变不透 |

区域组名同样是接口：

```
00_基地环境 / 01_入口湖景与桥梁 / 02_园艺植物生产实训中心
03_芍药种植资源创新基地 / 04_数智农业实践研学中心
```

> 改名会导致对应构件失去动效，但不会报错 —— 表现是"风机不转了""灯不亮了"。

## 5. 已知模型问题（建议在源模型里修）

| 问题 | 影响 | 建议 |
|---|---|---|
| 湖心岛的草坪面片是**方形**，且比岛体大一圈，浮在水面上 | 近景可见一块突兀的绿方块 | 在建模时把岛面裁成岛形，或缩小到石砌内圈 |

## 6. 更新模型的操作

1. 在建模流程里重新导出 `qinhu_base_digital_twin.glb`，覆盖原文件；
2. 若区域/设备有增删，同步更新 `scene_manifest.json`；
3. 浏览器 `Ctrl+F5` 刷新。

如果新增了可驱动构件，在 `site.js` 的构件索引段加一条正则即可，例如：

```js
} else if (/外遮阳网/.test(name)) {
  shadeNets.push({ mesh: o, mat: o.material.clone(), region });
}
```

## 8. 修复记录（2026-11-01）

这一轮处理了三件事：**画面上的白色闪烁点、桥没接上岸、默认视角**。

### 8.1 白色闪烁点：风机枢轴被反复套娃

**现象**：屏幕上时不时出现细长的白色亮片，像一只小鸟翅膀从地面划到天空，
一闪就没了，全屏各处都有。用 Babylon 的 sandbox 打开同一个 glb 却没有。

**根因**（`scene/site.js` 的旧 `makePivotFor`）：

原来是在 `root.traverse()` 的回调里直接改树的：

```js
parent.add(pivot);      // 往 children 里 push 了新节点
parent.remove(mesh);
pivot.add(mesh);
```

three 的 `traverse` 是按下标遍历 children 的，**边遍历边往 children 里 push，
新加的 pivot 会被继续访问到**；它的子节点又是一片名字匹配的叶片，于是对同一片
叶子反复套 pivot。实测：

| 项目 | 数量 |
|---|---|
| 叶片网格 | 154 |
| 生成的 pivot | **168**（正常应该是 35 台） |
| pivot 嵌套层数 | 最多 4 层 |

每套一层都会执行一次 `geometry.translate(-c)`。这个模型的叶片顶点是**绝对坐标**，
第一层的 `c` 是叶片在场地里的位置（70 m 量级）；第二层几何已经被平移过，`c` 变成 0，
于是 `mesh.position` 被写成 0 —— 叶片从原位**跳到世界原点**，并绕原点旋转。

一片 0.3×0.8 m 的白色薄片绕场地中心扫出半径几十米的圆，投影到屏幕上就是
"白鸟从地面划到天空"。Babylon 不转叶片，所以看不到。

**修复**：

1. 先完整收集叶片，再统一处理，绝不在遍历中改树；
2. 用世界矩阵反解保持原位置，`geometry` 一律不动（它可能是共享的）；
3. 按空间邻近（< 2 m）把同一台风机上的几片叶子归到一个枢轴，整体旋转。

实测修复后：35 台风机、154 片叶片全部落在 `x 0.9~92.4 / z -71~34` 的正常范围内，
没有一片跑到原点。

另外顺手压掉了两类"材质型闪烁"：

| 项目 | 修改 |
|---|---|
| 环境反射强度 | 1.0 → 0.7（细金属杆上的极亮小高光） |
| 镀锌钢 roughness | 0.45 → ≥0.58 |
| 农膜 roughness | 0.38 → 0.62 |
| 透光板 roughness | 0.16 → 0.34 |
| 叶片投影 | 关闭（薄片投影有 acne，且叶片在转，影子会扫） |

**验证**（连拍 10 帧，逐像素找"上一帧 <200、本帧 >248"的新增纯白像素）：

| 指标 | 结果 |
|---|---|
| 新增纯白像素 | **0** |
| 最大连通块 | 0 |

### 8.2 桥没有接到岸

**现象**：木栈桥东端悬在水面上方约 5 m。

**数据**：桥面由 53 块 `木栈桥桥面板` 拼成，x 只铺到 **91.93**，而湖面东边界是 **96.84**。

**修复**：`weldBridge()` 按桥面实际数据补两段引桥（东 5.8 m、西 1.1 m），
坡面从桥端高度降到岸边 0.34 m，宽厚与桥板一致，栏杆按同样的间距补 3 道横杆 + 立柱。

这里又踩到一个坐标系坑：区域组 `01_入口湖景与桥梁` 带 −90° 绕 X 的旋转
（Blender 的 Y-up 转 Z-up 留在节点上），世界几何直接挂进去，y 和 z 会互换，
引桥会跑到天上。做法是统一乘一次 `parent.matrixWorld` 的逆矩阵。

### 8.3 默认视角：站在大门后向西看

模型的大门在东侧（`0183/0185_东侧入口门柱`，x≈108，z=±8），所以"进门第一眼"是自东向西。

`buildViews()` 新增 `entry` 视角：机位从模型里找门柱位置动态算，站在门内侧 6 m、
眼高 1.75 m，fov 50；主界面与模型页都以它作为初始镜头。

### 8.4 顺便修掉的模型问题

| 问题 | 处理 |
|---|---|
| 44 个构件丢了材质（显示为白树/白块） | 按构件名优先、形态兜底补材质：透光板→半透膜、钢/架/梁→金属、墙/板→浅灰、高窄无名的→树冠 |
| 端墙发黑 | 上一版按尺寸判定把 `0625_端墙透光板` 误判成树冠刷成深绿；改为先看名字后看形态，现在端墙是半透明透光板，能看见内部骨架与风扇 |
| 湖心岛草坪是 12×9 的绿色方块，比护岸还大 | `fixIslandLawn()` 换成椭圆（缩到 0.93 倍），与石砌护岸贴合 |
| 棚内一片漆黑 | 膜与棚膜加 `emissive` 模拟棚内漫射光 |

> 关于 8.4 的第一条要记牢：**按包围盒猜材质是不可靠的**。`端墙透光板` 高 4 m、
> 面宽 7 m，完全符合"高而窄=树"的判据。判定必须有名字优先、尺寸兜底两层。
